SimKit 0.3 (2026-11-14) -- TESTING (toolkit owner only; users never need this file)
=====================================================================================

What is in the kit
  SimKit.java                 the macro users play: Save as new run, Run on cluster (Linux only), Tracker, Names,
                              Standard reports, Mesh study, Calculators. One file, ordered by tool (sections in this
                              order: constants and the Tool enum, entry point and batch actions, menu window, project
                              and runs, run records, simulation values, Save as new run, Run on cluster, Tracker,
                              Names, Standard reports, Mesh study, Calculators, configuration, batch tests, helpers)
  lib/generic/SimKitCalc.java calculators (opened by the Calculators button); data in lib/generic/data/*.csv
  config/cluster.csv          bsub command and options for Run on cluster
  config/standard_reports.csv the reports, monitors and plots of Standard reports (optional criterion and mean)
  config/naming.csv           type prefixes (IN, OUT, OPEN, WALL, SYM, IF) and the boundary types that fit each
  config/comment_template.txt optional: the comment template of the tracker (absent = built-in)
  buttons/                    one macro per toolbar button; see buttons/README.txt
  tests/                      validation runners (this file)
The kit lives in ONE shared folder (Windows and Linux mounts of the same share). Projects do not: the first Save as
new run asks for the project folder (any local or network folder).

Path map
  SimKit root = the folder that holds SimKit.java. Each macro finds it from its OWN location with the STAR-CCM+
  call resolvePath (no environment variable, no path written anywhere):
    SimKit.java "."   buttons/*.java ".."   lib/generic/SimKitCalc.java "../.."
  So the kit works wherever the folder is copied (any drive letter or mount point, Windows or Linux), as long as
  its inner layout is kept. Every kit file is reached from the root with a relative path written with '/'.
  Nothing is ever written inside the root.
  User side (never under the root), one project:
    <project>/simkit_project.txt                     project, description, created, created_by
    <project>/[group/]R<nnn>_<name>/R<nnn>_<name>.sim the run file (a run may sit in a group folder)
    <project>/[group/]R<nnn>_<name>/run.txt          name, based on, comment, status, hidden, mesh_* (key=value)
    <project>/[group/]R<nnn>_<name>/submit/          scripts and logs of Run on cluster
    <project>/[group/]R<nnn>_<name>/<any>/R<nnn>_<name>_iter_<n>.sim   copies returned by the cluster
    <project>/.simkit/run_numbers/R<nnn>.txt         run numbers taken (who, when); never removed
  SimKit looks 6 folder levels below the project for run.txt and .sim files, and 6 levels above a file for the
  project. Projects of SimKit 0.3 before 2026-11-14 (sims/ and record/R<nnn>.txt) are still read.

Site set-up (once)
  1. Copy the _SIMKIT folder anywhere on the share (e.g. S:\CFD\_SIMKIT on Windows = /mnt/cfd/_SIMKIT on Linux).
     Nothing else to configure: no environment variable, no path in the macros.
  2. Edit config/cluster.csv (bsub command, queue, cores).
  3. Each user plays buttons/SimKit_InstallButtons.java once (File > Macro > Play Macro, from the share): the SimKit
     buttons go to a SimKit toolbar (STAR-CCM+ favourite macros), pointing at the files on the share (do not
     copy them: each button finds the root from its own location and always runs the current kit).
  4. Put the guideline docx in Google Docs.

A. BATCH VALIDATION (no GUI; about 15 min)
  Windows 10/11:
    powershell -ExecutionPolicy Bypass -File <SimKit root>\tests\Run-SimKitTests.ps1 -Star "<STAR install>" ^
        -LicenseFile "<licence file or port@server>" -TestRoot C:\SimKitTest
  Linux RHEL 7/9:
    bash <SimKit root>/tests/run-simkit-tests.sh --star /opt/Siemens/<release> --license <port@server> \
        --test-root ~/SimKitTest
  Both copy the kit to <TestRoot>/_SIMKIT, build a small test sim (tests/BuildSimKitTestSim.java), make it run R001
  of the project <TestRoot>/cases/SIMKIT_TEST (R001_base/R001_base.sim + run.txt) and run:
    02 calculator self-check
    07a standard reports (saves the sim) | 07b the same again (must add nothing) | 07c parametrize mesh
    07e mesh study (coarse and medium levels, meshed, saved as runs) | 07f names (the Names table in the log,
        nothing renamed) | 07g pre-submit check (the lines of Run on cluster, in the log)
    08 tracker button | 08b/08c toolbar buttons install / remove (the user's settings.props is restored)
    09 optional short solver run (-RunSolver)
    10b save as new run (batch: next run, same name) | 11 tracker (writes case_tracker.csv)
    11b open sim (the tracker's Open in STAR-CCM+) | 11c project test (new project, runs, returned copy, submit
        script without bsub, new project from a run)
  Then paste <TestRoot>/results/PASTE_THIS.txt (the licence location is masked) to whoever maintains SimKit.
  Expected: every exit code 0 and no "Exception" in results/*.log.
