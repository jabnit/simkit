SimKit 0.2.1 (2026-11-11) -- TESTING PROCEDURE (Windows 10/11 and Linux RHEL 7/9; batch-validated on Windows, see J, K)
===================================================================

SimKit.java and the ISO macros were written WITHOUT access to a STAR-CCM+ installation. Their plain-Java
logic (CSV, case numbering, versions, diff, rules, write guard; in 0.2 also the parameter-sync path tokenizer,
reflection resolver, tolerance compare, state classification, baseline lookup and managed names) was compiled
and exercised against stub classes, but every STAR-CCM+ API call is unverified until it runs in YOUR 2402
(19.02) build. Test on COPIES only, in a test share, never in S:\CFD.

New in 0.2: menu groups PARAMETERS (17 Parameter sync..., 18 Non-default settings report, 19 Snapshot
baseline (owner)) and TOOLS (20 Engineering calculators = lib\generic\SimKitCalc.java). Section F below is
the parameter-sync test; the new uncertain calls U35-U44 are listed at the end of section E.


A. SET UP A TEST SHARE (10 min)
-------------------------------
1. Create C:\SimKitTest\_SIMKIT and copy the delivered _SIMKIT folder into it
   (SimKit.java, VERSION.txt, TESTING.txt, lib\..., google\...).
2. Copy the delivered config\ folder too (naming_rules, tag_rules, group_rules, stages, projects, links,
   parameters_ISO, template_objects_ISO). In links.csv replace the REPLACE_WITH_ID placeholders (rows that
   still contain REPLACE are skipped). If a CSV is missing, SimKit falls back to built-in defaults for
   naming_rules, tag_rules, group_rules, stages and projects (ISO with CF;C1;C2;C3;VV); the About tool lists
   which files were found. Optional: config\rename_rules.csv (object_type,find_regex,replace) for Auto-name.
3. Point SimKit to the test share: in a Windows command prompt run
       setx SIMKIT_SHARE C:\SimKitTest
   then close and restart STAR-CCM+ (it only sees variables set before it started).
4. Copy a real sim that has regions, a mesh, some reports/monitors/plots/scenes to
   C:\SimKitTest\scratch\copy.sim and open it in STAR-CCM+ 2402.


B. COMPILE CHECK
----------------
5. File > Macro > Play Macro... > C:\SimKitTest\_SIMKIT\SimKit.java
   - Compile errors appear in the Output window as  SimKit.java:<line>: error: ...
     Fix them with section D, then play again. Expect a few at most: each uncertain call is isolated.
   - The first Output line must read  "[SimKit] SimKit 0.2 (...) | share C:\SimKitTest | interactive".
     If it says "batch: no visible window ..." instead, run  setx SIMKIT_GUI 1, restart STAR-CCM+, retry.
   - The menu window opens with seven groups in two rows. Each tool shows its log in a dialog afterwards and prints
     it to the Output window. A line "n/a (...)" means one API call failed and was skipped: note its tag
     (section E) and the message.

D. FIXING AN API MISMATCH (compile error or "n/a (NoSuchMethodError / ClassCastException ...)")
---------------------------------------------------------------------------------------------
Every uncertain STAR call carries a tag [Unn] on its line; section E says what it does.
 1. In STAR-CCM+ 2402: File > Macro > Start Recording... > C:\SimKitTest\rec.java
 2. Do ONLY the single GUI action given for that tag in section E (column "record").
 3. File > Macro > Stop Recording. Open rec.java in a text editor.
 4. Copy the generated line(s) to the tagged place in SimKit.java (or the ISO macro), renaming the
    recorder's variables to the ones in the code: simulation_0 -> sim, boundary_0 / report_0 / ... -> the
    object variable on that line (o, ob.o, p, s, t, ...), userTag_0 -> tag, units_0 -> u.
    Keep the surrounding try/catch. If rec.java imports a package SimKit lacks, copy that import line.
    Example (U06): recorded
        simulation_0.get(TagManager.class).setTags(boundary_0, new NeoObjectVector(new Object[] {userTag_0}));
    would become, in addTag():
        tagManager().setTags(o, new NeoObjectVector(new Object[] {tag}));
    (and if the only recorded form REPLACES all tags, combine tagsOf(o) with the new tag first, because
    Auto-tag must never remove manual tags).
 5. Play SimKit.java again. A line you cannot fix yet: comment it out and write
        throw new UnsupportedOperationException("U06 not adapted");
    the tool then logs n/a for it and everything else keeps working.
 Getters (U01, U05, U12, U15, getDefinition in U10) are called through Reflect.tryCall with a method-name
 string, because the recorder never records getters. They always compile; if they report n/a, look the
 getter up in the Java API reference of your installation (STAR-CCM+ Help > Java API, or <install>\doc)
 and change the name string.
 "cannot find symbol: class X": X lives in another package -- record any action on X; the recorder's
 import list shows the package; add that import.

F. PARAMETER SYNC TEST (on copies; about 45 min)
------------------------------------------------
Background: a setting from config\settings_catalogue.csv gets a managed parameter p_<FAMILY>_<inst>_<prop>
(FAMILY = MESH|SOLV|STOP|BC|PHYS) only when it differs from its baseline. Baseline order: template baseline
(_SIMKIT\templates\<PROJ>\<template>_baseline.csv, per object), else factory defaults
(_SIMKIT\config\factory_defaults_<release>.csv, per catalogue row; newest release if yours is missing, with a
note), else "no baseline" (NB: report only, never parameterised). States in the preview:
  S0 at baseline: nothing        S1 differs, not linked: create P, link    S2 linked to P, differs: OK
  S3 linked to P, P = baseline: unlink, delete P if unreferenced           S4 P exists, direct edit: P = value, relink
  S4b P exists, setting typed back to the baseline: delete P if unreferenced
  S5 linked to a user parameter / expression: report only    NP not parameterisable (or link refused): report only
  OFF setting not present because its option is not selected (STAR "Class: ..." message, e.g. a custom
      value not activated, a wall that is not set to fixed temperature): report only, not an error
  NA path not resolvable in this sim (wrong catalogue path or API change): see the n/a reason (section D)

F1 Harvest factory defaults (owner action; once per STAR-CCM+ release)
   1. File > New Simulation (blank). Create ONE default object of each source, changing NOTHING:
      a part + region, an Automated Mesh operation (surface remesher + polyhedral + prism layer mesher) with one
      surface custom control and one volumetric custom control; a physics continuum (3D, gas, segregated flow,
      segregated fluid temperature, k-omega, implicit unsteady); boundaries: one mass-flow inlet, one pressure
      outlet, one wall. Stopping criteria exist by default.
   2. Save it as C:\SimKitTest\scratch\blank_defaults.sim (outside PROJECTS: no case is needed).
   3. SimKit > 19. Snapshot baseline (owner) > Factory defaults. The preview lists one row per catalogue row
      and, under "Not written", the rows with no readable instance (reasons in the Output window: every
      "ClassNotFoundException"/"NoSuchMethodException" is a catalogue path to correct -- see U37/U44).
      Confirm -> C:\SimKitTest\_SIMKIT\config\factory_defaults_<release>.csv. Open it: si_value in SI.
      Run it twice: the first file is kept as factory_defaults_<release>.csv.<timestamp>.bak.
      Note: the surface and volumetric custom-control rows are OFF until a custom value is activated on the
      control (that is STAR behaviour, not an error); activate the values you want baselined before step 3.
F2 Snapshot the template baseline (owner action; whenever the template changes)
   4. Open (a copy of) the project template, e.g. ISO_template_v01.simt. 19. Snapshot baseline > Template
      baseline > project ISO -> C:\SimKitTest\_SIMKIT\templates\ISO\ISO_template_v01_baseline.csv (template
      name from projects.csv, column template). One row per setting and object (row_id, instance, si_value,
      definition, ...). The instance names (MO_30_autoMesh, F_air/BRN_x.IN_air, ...) must equal the names in
      the cases; renaming an object in a case makes it fall back to the factory defaults.
   5. Write guard: 19 is the only tool that writes inside _SIMKIT; it asks "OWNER ACTION ..." first. Any other
      tool that tried would log "refused to write outside ...".
F3 Case lifecycle (in a case made from the template: 1. Initialise case first)
   6. 17. Parameter sync on the untouched case -> preview shows nothing pending (S0 counts in the header; NB
      rows only for objects/settings without baseline). Close.
   7. In the mesh operation MO_30_autoMesh (Default Controls > Base Size) change the base size, e.g. 5 mm -> 4 mm.
      17. Parameter sync -> row "MO_30_autoMesh  MESH01 baseSize  S1  create p_MESH_MO30autoMesh_baseSize".
      Apply -> Tools > Parameters has p_MESH_MO30autoMesh_baseSize with dimensions Length, units mm, value 4;
      the Base Size field shows ${p_MESH_MO30autoMesh_baseSize}; the mesh value did not change (still 4 mm).
      Parameters are in G30_meshParams (other p_ parameters in G35_caseParams), or the log says groups are not
      supported. audit\paramsync_<sim>.csv has every row (S0 summarised per catalogue row).
   8. Run 17 again -> nothing pending; the row is S2 (information only).
   9. Direct edit: type 3 (mm) directly into Base Size (replacing the ${...}). 17 -> S4 "direct edit adopted";
      Apply -> parameter = 3 mm and Base Size linked again.
  10. Back to default via the parameter: set p_MESH_MO30autoMesh_baseSize back to the template value (5 mm).
      17 -> S3 "back to default: unlink, delete ... if unreferenced"; Apply -> second dialog "Delete these 1
      managed parameter(s)?": answer No first -> Base Size shows the literal 5, the parameter is kept (result
      "kept (deletion declined)"); 17 again -> S4b; Apply + Yes -> parameter deleted, Output line
      "DELETED managed parameter p_MESH_MO30autoMesh_baseSize (...)".
  11. Back to default by hand: link again (step 7), then type the template value directly into Base Size ->
      17 -> S4b -> Apply + Yes -> deleted.
  12. Protection: create a user parameter p_test = ${p_MESH_MO30autoMesh_baseSize}*2 (after step 7), then go
      back to default -> the result says "kept ... (still referenced)". User parameters (p_mdotAir, p_tEnd, ...)
      are never modified, unlinked or deleted; a setting linked to one shows S5.
  13. Deselect: produce two pending rows (e.g. base size + time step), untick one in the preview, Apply ->
      only the ticked one changes; the other is "pending (deselected)" in the CSV and still pending in 17.
  14. "check" rows (e.g. MESH04 curvature points, SOLV02 velocity URF): change one, 17 -> S1 "(tried ...)";
      Apply -> either linked, or "NP: not parameterisable in this build (...)" and the just-created parameter
      is removed again. If NP, set that row's parameterisable to "no" in the workbook/CSV.
  15. Save new version with a pending item -> the preview appears before saving; Cancel -> the save goes on
      and audit\setup_audit_<new>.csv contains "PARAMSYNC,<object>,<row> <prop>,pending S1: ...".
      With nothing pending the save shows no extra dialog.
  16. 9. Pre-run check with a pending item -> "WARN  parameter sync  1 pending item(s) ...".
  17. 18. Non-default settings report -> Output table + audit\nondefault_<sim>.csv: every setting that differs
      from its baseline (linked or not, parameterisable or not).
  18. Batch: SIMKIT_ACTION=audit (section C) -> setup audit has NONDEFAULT + PARAMSYNC sections; the sim is not
      changed (compare the parameter list before/after).
  19. Units check: change a boundary mass-flow rate in g/s or a temperature in C if your build offers it, then
      sync: the parameter takes the units of the setting and the SI value must be identical (SimKit verifies
      the value after linking and restores the old definition if it changed: result "link not taken or value
      changed ... restored").
Catalogue names: the BC props were renamed tStatic, uMag, tuInt, tWall in settings_catalogue.csv (0.2), so
managed names such as p_BC_<inst>_tStatic pass the parameter naming rule.

G. ENGINEERING CALCULATORS (lib\generic\SimKitCalc.java, SimKit 0.2)
Unit-tested outside STAR: Core physics and Library were run with JDK 23 (--release 11), 95/95 checks:
Celik GCI example in 2-D (p=1.534, phi_ext=6.1685, GCI=2.17 %), Gamma(0.5)=sqrt(pi), AFR, Rosin-Rammler

K. LINUX (RED HAT 7 / RED HAT 9)
SimKit and the library macros are the same files on Windows and Linux. What differs:
  - Share: default S:\CFD on Windows, /mnt/cfd on Linux (constants SHARE_ROOT_WINDOWS / SHARE_ROOT_LINUX at the
    top of SimKit.java, SimKitCalc.java and the ISO macros; edit both once for your site). SIMKIT_SHARE overrides
    it on both (Linux: export SIMKIT_SHARE=/mnt/cfd in ~/.bashrc, before starting STAR-CCM+).
  - Path comparisons are case-insensitive on Windows only; on Linux the file and folder names must match exactly.
  - Write batch run script: run_<CASE>.sh is made executable on Linux (u+x,g+x); on a CIFS mount without POSIX
    permissions start it with  bash run_<CASE>.sh. The .bat keeps a SIMKIT_SHARE already set by the user.
  - Open guideline / workbook: uses java.awt.Desktop, else xdg-open (Linux) / rundll32 (Windows).
  - Register rows and case cards store paths relative to the case folder with '/', identical on both systems.
Batch validation on Linux (same steps and same PASTE_THIS.txt as Run-SimKitTests.ps1):
    bash <SHARE>/_SIMKIT/tests/run-simkit-tests.sh --star /opt/Siemens/<release> --license 1999@licserver \
         --test-root ~/SimKitTest
  (--star = launcher .../star/bin/starccm+ or the installation root; --license optional, never printed: masked
  as <licence>; --np, --star-args "-power -podkey ...", --sim, --run-solver, --interactive, --skip-sync as in
  the PowerShell runner.) Output: ~/SimKitTest/results/PASTE_THIS.txt + simkit_test_results_<ts>.tar.gz.
  The script needs bash >= 4.2, GNU grep/sed/awk and tar only (RHEL 7 and 9 default). It was dry-run against a
  stand-in launcher (all steps, redaction of the licence path/lines and of 'confidential' paths in both the
  paste file and the archive); it has NOT yet run on a real Linux STAR-CCM+ install.
GUI on Linux: Play Macro and the SimKit menu are Swing dialogs; they need a display (local X11, VNC, or
ssh -X). Without a display STAR-CCM+ must run with -batch (SimKit then uses its batch actions).
Platform support: check the Siemens "supported platforms" table of the release you install -- recent releases
may no longer list RHEL 7; SimKit itself has no OS-specific requirement beyond the STAR-CCM+ JVM (Java 11+ level).
