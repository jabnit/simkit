SimKit 0.3 (2026-11-11) -- TESTING (toolkit owner only; users never need this file)
=====================================================================================

What is in the kit
  SimKit.java                 the macro users play (Save as new, Check, Export results + small tools)
  lib/generic/SimKitCalc.java calculators (opened by the Calculators button); data in lib/generic/data/*.csv
  config/projects.csv         projects and their configuration codes (offered when a case is created)
  config/naming_rules.csv     the two checked name patterns (parts, part surfaces)
  config/links.csv            what the Guideline button opens (paste the Google Doc / Sheet links)
  config/material_folders.csv team folders of MatML material files (*.xml) for Calculators > Material properties
  buttons/                    one macro per toolbar button (Menu, SaveNewVersion, Check, ExportResults,
                              Calculators); see buttons/README.txt
  templates/ISO/tools/        template-owner macros for the ISO template (not part of the user workflow)
  tests/                      validation runners (this file)
The kit lives in ONE shared folder (Windows and Linux mounts of the same share). Cases do not: the first Save as new asks
the user for the folder that will hold the case folder (any local or network folder).
The full 0.2.1 kit (tags, groups, parameter sync, register script, batch-script writer) is kept outside the kit
in SimKit_deliverables/_archive/SimKit_0.2.1_full for a later update.

Path map
  SimKit root = the folder that holds SimKit.java. Each macro finds it from its OWN location with the STAR-CCM+
  call resolvePath (no environment variable, no path written anywhere):
    SimKit.java "."   buttons/*.java ".."   lib/generic/SimKitCalc.java "../.."   templates/ISO/tools/*.java "../../.."
  So the kit works wherever the folder is copied (any drive letter or mount point, Windows or Linux), as long as
  its inner layout is kept. Every kit file is reached from the root with a relative path written with '/', in one
  place per macro:
    SimKit.java        config/projects.csv, config/naming_rules.csv, config/links.csv, VERSION.txt,
                       lib/generic/SimKitCalc.java
    SimKitCalc.java    lib/generic/data/ (fluids.csv, materials.csv, emissivity.csv)
    buttons/*.java     SimKit.java, lib/generic/SimKitCalc.java
    ISO tools          templates/ISO/tools/parameters_ISO.csv, templates/ISO/tools/template_objects_ISO.csv
  Nothing of the kit is addressed in any other way, and nothing is ever written inside the root.
  User side (never under the root): the sim file the user opened, and for a SimKit case
    <folder chosen at the first Save as new>/case_list.csv
    <folder chosen at the first Save as new>/<CASEID>/sim/<CASEID>[_label]_v<nn>.sim, case_identity.txt
    <folder chosen at the first Save as new>/<CASEID>/record/  results/csv/  results/img/
  case_identity.txt keeps the full path of the parent case's sim.

Site set-up (once)
  1. Copy the _SIMKIT folder anywhere on the share (e.g. S:\CFD\_SIMKIT on Windows = /mnt/cfd/_SIMKIT on Linux).
     Nothing else to configure: no environment variable, no path in the macros.
  2. Edit config/projects.csv (projects, configuration codes) and config/links.csv (Google Doc / Sheet links).
  3. Each user plays buttons/SimKit_InstallButtons.java once (File > Macro > Play Macro, from the share): the SimKit
     buttons go to a SimKit toolbar (STAR-CCM+ favourite macros), pointing at the files on the share (do not
     copy them: each button finds the root from its own location and always runs the current kit).
  4. Import Google/SimKit_Case_List_ISO.xlsx into Google Sheets and put the guideline docx in Google Docs.
